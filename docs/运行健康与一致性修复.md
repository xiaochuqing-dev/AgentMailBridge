# 运行健康与一致性修复

## 邮件运行状态

“文件与数据 > 邮件运行状态与数据维护”汇总目录同步、历史导入、发件状态、Sent 对账、邮件事实问题和存储占用。页面明确区分正常、部分完成、正在恢复和需要用户处理；`delivery_unknown` 始终显示“绝不会自动重发”。

目录明细包含最后成功、最后尝试、当前阶段、连续失败、UIDVALIDITY 变化和重新对账标记。发件汇总区分待确认、执行中、等待 Sent、结果不确定、归档待恢复、已完成和已取消/过期。问题总数使用完整计数，明细最多展示 100 项以保持界面有界。

## 只读扫描

一致性扫描核对数据库与 package 目录、manifest identity、raw/资源存在性和 SHA-256、相对路径、ownership、membership、direction conflict、request/outbound/package 关联、Sent mapping、checkpoint、lease、线程关系、发件快照、工作副本和 secret canary。

扫描默认只报告并更新 `consistency_scan_runs` 与 `health_issues`。Sent 与本地恢复产生的 weak、unmatched、ambiguous 记录保留实际 evidence_type、candidate_count 和非敏感决策原因；扫描只把未解决记录展示为问题，不据此改写关联。结果不包含正文、附件内容、凭据或完整私人路径。重复执行会解决已经消失的问题，不删除事实。

## 单项修复

扫描结果按发件恢复、邮件事实、Sent 对账、同步进度、存储和安全分类。只有白名单动作可执行：恢复固定 MIME 的发件归档、用本地/Sent 确定证据重新对账、分类一个过期 lease，以及结束一个确已过期的待确认请求。

修复必须使用最近一次扫描的 issue_id，一次只选一项，并重新验证问题仍开放。执行前创建并校验 SQLite 在线备份；动作使用既有事务、lease 和原子发布机制；结果写入 `consistency_repair_runs`，只记录 ID、动作、状态、备份文件名和非敏感结果代码。

duplicate、ambiguous、direction conflict、Hash 不一致、缺失文件、ownership 冲突和可能涉及唯一恢复资料的问题只允许人工处理。修复不会调用 SMTP、删除永久 package、覆盖文件、自动合并候选或返回凭据。

## 安全清理与诊断

安全清理与一致性修复是不同工作流。清理只处理满足状态与保留期的临时快照，并支持 dry-run；修复只处理扫描问题。脱敏维护报告与诊断包不包含邮件正文、附件、token、授权码或完整路径。
