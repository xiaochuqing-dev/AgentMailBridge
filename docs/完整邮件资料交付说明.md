# 完整邮件资料交付说明

完整邮件资料是内部 Mail Package 的受控副本，不是移动归档，也不是 Agent 自动判断相关邮件。用户或 Agent 必须先明确选择一封稳定 mail_id/package_id，并选择已授权的邮件资料输出目录。

`prepare_mail_resources` 保持兼容：默认 `mode=resources` 使用原有 resource_ids；`mode=complete` 准备整封邮件。工作区优先传入 `list_agent_workspaces` 返回的 `workspace_id`；兼容参数 `target_workspace` 仍可使用工作区 ID 或完整路径，但不能与 `workspace_id` 同时提供。只有一个可用工作区时可省略两者。输出位于允许目录下的 `.agentmailbridge/mail/<mail-id>/`。同一 package_id、目标目录、源归档指纹和逐文件 Hash 未变化时默认返回 `reused=true` 并复用原目录。

工作副本缺文件或大小/Hash 变化时绝不静默覆盖。`rename` 会保留原副本并准备到新目录，返回 `existing_copy_modified=true`；`error` 返回明确拒绝；只有用户显式选择 `overwrite` 才原子替换。删除工作副本不触及 DATA_ROOT 内的正式归档。

完整目录包含：

```text
完整邮件资料/
  邮件正文.md
  原始邮件.eml
  邮件信息.json
  原始归档manifest.json
  完整资料manifest.json
  附件/
  邮件内图片/
  下载文件/
```

邮件信息包含账号归属、发件人、收件人、抄送、时间、主题和 package_id。完整资料 manifest 逐项记录 resource_id、内部类型、来源关系、相对路径、大小和 SHA-256；普通附件、MIME 内嵌图片和已经进入正式归档的受控下载都会复制。不存在的类别保留为空目录，不会联网补下载。

准备前重新验证 package ownership、resource ownership、manifest 相对路径、DATA_ROOT、Client 资料目录范围和全局允许目录。每个源文件必须匹配归档事实中的大小与 SHA-256；复制后再次验证目标。所有内容先进入同父目录短名 staging，全部闭合后一次重命名发布；失败清理 staging，overwrite 失败会恢复原目录。

准备前后对内部 package 文件取 Hash 快照，任何变化都使操作失败。输出不包含邮箱密码、授权码、OAuth Token、Client token、SQLite、无关邮件或未归档的外部文件。审计只记录 Client、邮件、目录 ID、模式、数量、Hash 和结果，不保存正文或附件内容。

稳定错误包括 `complete_mail_prepare_denied`、`complete_mail_prepare_failed` 和 `complete_mail_hash_mismatch`。路径越界、ownership 不匹配、源文件篡改、目标联接逃逸或 Client 目录越权都必须在发布前拒绝，且不得留下半成品目录。
