# v1.7.1 长期运行验证计划

## 状态

这是发布后可继续执行的 7 至 14 天 dogfood 计划，不代表已经完成。最终验收报告必须单独记录本次实际持续运行时长，不能把计划时长计入实测。

## 环境与边界

使用用户自己的隔离测试邮箱和已安装版 AgentMailBridge。QQ 与 163 只在测试账号之间发信；Gmail 保持只读。不得自动化 OAuth，不删除或移动私人服务器邮件，不把邮箱地址、主题、正文、附件名、路径或 secret 写入证据。

每天保留脱敏计数：运行时长、同步次数、`no_changes`、partial/failed、各目录最后成功、UIDVALIDITY 变化、发件请求、SMTP 尝试、`delivery_unknown`、`sent_archive_failed`、Sent matched/ambiguous/unmatched、stale lease、临时资料字节、清理预览/执行、手动修复次数、Agent 自然任务成功率和进程重启次数。

## 每日场景

第 1 至 2 天验证安装、覆盖升级、开机/托盘、Inbox/Sent 多轮无变化、Codex Desktop/CLI、Claude Code 和 Hermes 的读取与状态查询。

第 3 至 4 天在测试邮箱间执行 confirm 与 autonomous，新建、回复、回复全部、转发、多附件、Sent 延迟回流和幂等重放；确认 SMTP 调用次数与本地事实一致。

第 5 至 6 天通过网页或现有客户端发信，移动测试邮件到 Archive/自定义目录并增加/移除 Label；核对单一 package、多 membership、direction 和 server presence。

第 7 天执行安全清理预览、一致性扫描、数据库备份验证、程序正常重启和脱敏诊断导出。若继续至 14 天，重复自然任务并覆盖 Windows 睡眠/唤醒、网络短断、长时间托盘、磁盘空间告警和计划内进程终止。

## 故障注入

只在隔离数据和测试请求上注入 before lease、after lease、after MIME、before SMTP、DATA started、SMTP accepted、accepted 后和 archive 后中断。每次核对 SMTP 次数、request/lease/event、package、raw Hash、恢复状态和幂等重放。DATA 后未知不得自动重发，accepted 后只能恢复归档。

## 退出标准

P0 必须为零：重复真实发送、永久事实丢失、错误合并、secret 泄露或越权访问均立即停止测试。P1 包括长期卡住 sending、checkpoint 清零、Sent 对账持续失效、临时资料无界增长和安装版不稳定；需修复并重新开始相关观察窗口。

每天的证据只保存脱敏 JSON/文本和计数。第 7 或第 14 天汇总实际运行时长、未解决 P1/P2、手动处理次数与结论，再决定是否更新最终报告；不得自动发布 GitHub Release。
