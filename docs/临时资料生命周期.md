# 临时资料生命周期

## 数据类别

永久资料包括 received/sent Mail Package、raw.eml、正文、资源、manifest、数据库业务事实与审计。它们不进入自动清理。

可管理临时资料包括发件请求附件快照、固定 MIME staging、收件/发件 package staging 和 Agent 工作副本。工作副本属于用户目录，不由自动清理覆盖或删除。

## 发件快照保留

pending、sending、`delivery_unknown`、`sent_archive_failed`、recovery_required 及仍有活跃 lease 的请求必须保留全部恢复资料。只有已取消、已过期、确定未发送或已完成且超过保留期的请求可进入安全清理候选。

预览返回 request ID、类别、估算字节和原因，不返回正文、附件名或完整私人路径。执行可限定 request_ids，一次只处理预览中的安全候选。

## 两阶段清理

清理先把所选快照原子移动到 DATA_ROOT 内隔离区，再以数据库事务提交 `snapshot_cleaned_at` 和 `cleanup_records`，最后删除隔离内容。崩溃恢复根据事务状态完成删除或恢复原目录，不静默覆盖并发创建的内容。

任何 Hash、路径、ownership、状态或 lease 变化都会使候选失效。结果不确定邮件和唯一恢复 MIME 永不因年龄单独删除。

## Staging 与容量

package 与普通文件先写同目录短名临时文件，flush、fsync 后原子替换；Windows WinError 5/32 只做有界短重试。写入前检查目标卷可用空间，大 raw MIME 和附件不足时在发布前失败，不暴露半成品。

一致性扫描只报告超过阈值的 staging 残留；活动 staging 不作为孤立文件。用户应先确认没有活动任务和可用备份，再处理残留。
