# 发件状态机与崩溃恢复

## 固定事实

每个通用发件请求由 Client 与 idempotency key 唯一标识。执行前固定 Message-ID；MIME 构建后固定原始 bytes、大小和 SHA-256。后续恢复只能使用这份 MIME，不允许重新生成近似邮件。

## Lease 与阶段

SMTP 执行前通过 `BEGIN IMMEDIATE` 取得 `send_execution_leases` 单一租约，保存 owner、process、attempt、heartbeat、expires_at、当前阶段、固定 Message-ID 和 MIME Hash。只有当前且未过期的 owner 能继续记录阶段或续租；过期执行者不能恢复所有权。

`send_attempt_events` 持久记录 preflight、lease acquired、MIME built、before SMTP、DATA started、SMTP accepted、archive pending、archive completed 和失败结果。事件 details 只含非敏感状态与 Hash 事实。

## 崩溃分类

SMTP DATA 前中断：可以确定没有把邮件交给 Provider，恢复为 `definitely_not_sent`，用户可明确创建新请求。

DATA 已开始但没有接受证据：恢复为 `delivery_unknown`。系统不自动重发，也不把“可能未发出”当成“确定未发出”。用户可以等待 Sent 对账或在 GUI 记录人工结论。

SMTP 已接受：进入 `smtp_accepted` 或 `sent_archive_pending`。本地归档失败记录 `sent_archive_failed`；恢复只校验固定 MIME 并重建 outbound package，不调用 SMTP。

本地正式事实或服务器 Sent 提供唯一确定证据后，状态进入 `sent` 或 `sent_reconciled`。多候选保持 unresolved/ambiguous。

## 启动恢复与幂等

启动恢复忽略仍有活跃 lease 的请求，只分类过期租约和中断状态。恢复可重复执行；已完成请求和已有 package 返回现有结果。`delivery_unknown` 永不进入自动发送队列，Provider 接受后的归档恢复也不重新发送。

GUI 的单项一致性修复复用同一恢复函数，一次只处理用户选择的 request。修复前创建并验证 SQLite 在线备份，结果写入 `consistency_repair_runs`。
