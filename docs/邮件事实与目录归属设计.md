# 邮件事实与目录归属设计

## 核心模型

v1.7.2 继续把“邮件事实”和“当前位于哪些服务器目录”分开。一封物理邮件只有一个 `mail_packages` 正式事实，但可以有多条 `mail_package_mailboxes` membership。每条 membership 由 account_id、mailbox_id、UIDVALIDITY、provider UID、首次/最近发现时间、`currently_present` 和移除观察时间组成。

邮件从 Inbox 移到 Archive、从 Sent 移到自定义目录、增加或移除 Gmail Label 时，只更新 membership。服务器不再发现邮件时记录 `currently_present=0`；本地 package、raw.eml、资源、Hash 和历史关系都保留。一个目录同步失败不能撤销其他目录已经提交的归属。

## 唯一事实身份

Message-ID 是重要证据，但不是唯一身份键。Provider message id、账号、目录 UID/UIDVALIDITY、raw SHA-256、内容指纹和身份指纹共同参与查重；重复 Message-ID 但原文或身份指纹不同的物理邮件保持为不同 package。Gmail 多 Label、IMAP 多目录副本和 Sent 回流在证据一致时复用已有 package。

已有 package_id、account_id、resource_id、raw.eml 和历史 Hash 在迁移中保持不变。新 package_id 在账号与 Message-ID 基础上加入 v1.7.1 身份指纹，避免错误合并。

## Direction 证据

direction 与 mailbox 分离。`mail_direction_evidence` 保存本地 SMTP、SMTP accepted、服务器 Sent、服务器 Inbox、Provider 元数据和迁移证据。确定的本地发件或 Sent 证据可判为 outbound；明确收件证据判为 inbound；冲突进入 `direction_conflict`，不会根据当前目录名静默改写。

## Gmail 与 IMAP

Gmail API 一次消息可返回多个 labelIds；发现阶段未见的新 Label 会补记目录事实，但不会自动启用同步或扩大 Client 的 selected 权限。明确空 labelIds 不回退为列表查询来源目录。

IMAP 对每个目录形成独立 UID 快照。完整成功快照才可把未出现的旧 membership 标为 server absent；网络失败、部分结果和 UIDVALIDITY 变化都不能据此删除或覆盖永久事实。

## 查询与权限

按 mailbox_id 查询通过当前和历史 membership 关联 package。`all` 权限包含以后发现并启用的目录；`selected` 只允许明确选择的 ID。停用目录不能用旧 ID 绕过权限。事实查询只读，不移动、删除或标记服务器邮件。
